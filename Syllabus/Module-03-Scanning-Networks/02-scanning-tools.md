# 02 — Scanning Tools

This file catalogs the tools referenced across the module, with the syntax patterns that show up repeatedly in later files. Think of it as the toolbox; files `03`–`06` are what you build with it.

## 2.1 Nmap ("Network Mapper")

**Source:** https://nmap.org

Nmap is the workhorse of this entire module — essentially every technique described in files `03` through `06` has an Nmap flag attached to it. It sends specially crafted packets to a target and analyzes the responses to build a "map" of hosts, ports, services, and OS details. It scales from a single host to networks with hundreds of thousands of machines.

Core capabilities:
- TCP and UDP port scanning
- OS detection
- Service/version detection
- Ping sweeps
- Scriptable extension via the **Nmap Scripting Engine (NSE)**

Both network administrators (inventory, patch/service tracking, uptime monitoring) and attackers (live hosts, open ports, service versions, filter/firewall type, MAC details, OS fingerprint) use it — the tool doesn't care which hat you're wearing.

**Basic syntax:**
```bash
nmap <options> <Target IP address>
```

**Zenmap** is Nmap's official GUI front-end. It's used throughout the source material's screenshots — you type or build a command in the "Command" field, and results appear in tabs (Nmap Output, Ports/Hosts, Topology, Host Details, Scans).

Example from the lab material — a full-range aggressive scan:
```bash
nmap -p 1-65535 -T4 -A -v 10.10.1.11
```
This scans all 65,535 TCP ports (`-p 1-65535`), uses aggressive timing (`-T4`), enables OS/version/script/traceroute detection (`-A`), and runs verbose (`-v`). Output shows discovered open ports one at a time as the scan progresses, followed by a summary table of port/state/service/version.

## 2.2 Hping3

**Source:** https://salsa.debian.org (Debian packaging of the hping project)

Hping3 is a command-line packet crafting and scanning tool for TCP, UDP, ICMP, and raw IP. Where Nmap is more "point at a target, get a report," Hping3 is closer to a scriptable Swiss-army knife for building exactly the packet you want.

Capabilities include: network security auditing, firewall testing, manual path MTU discovery, advanced traceroute, remote OS fingerprinting, remote uptime guessing, custom TCP/IP packet crafting, fragmentation handling, file transfer over covert channels (its traceroute mode), idle host scanning, and firewalk-style discovery of open ports behind firewalls.

**Basic syntax:**
```bash
hping3 <options> <Target IP address>
```

### Hping3 Command Reference

| Purpose | Command | Notes |
|---|---|---|
| ICMP ping (echo request) | `hping3 -1 10.0.0.25` | `-1`/`--icmp` mode. Equivalent to a normal `ping`, but through hping3. |
| ACK scan on port 80 | `hping3 -A 10.0.0.25 -p 80` | Sets ACK flag; probes firewall/rule-set behavior. A basic packet filter lets ACK-set packets through; a stateful firewall blocks them. |
| UDP scan on port 80 | `hping3 -2 10.0.0.25 -p 80` | `-2`/`--udp`. Returns ICMP port-unreachable if closed; silence usually means open. |
| Collect initial sequence numbers | `hping3 192.168.1.103 -Q -p 139` | `-Q` collects all TCP sequence numbers generated by the target — useful for predicting ISNs. |
| Detect TCP timestamp support (firewall test) | `hping3 -S 72.14.207.99 -p 80 --tcp-timestamp` | Many firewalls drop packets lacking the TCP timestamp option; enabling it can reveal timestamp update frequency and target uptime. |
| SYN scan across a port range | `hping3 -8 50-60 -S 10.0.0.25 -V` | `-8`/`--scan` for a port range, `-S` for SYN flag — performs a SYN scan on ports 50–60. |
| FIN, PUSH, URG scan on port 80 | `hping3 -F -P -U 10.0.0.25 -p 80` | Sets FIN+PSH+URG together. No response ⇒ port likely open; RST response ⇒ port closed. |
| Ping-scan an entire subnet | `hping3 -1 10.0.1.x --rand-dest -I eth0` | Sends ICMP echo requests to randomized addresses across the whole `10.0.1.0/24` range on interface `eth0`. |
| Passive HTTP-signature sniffing | `hping3 -9 HTTP -I eth0` | `-9` sets listen mode; sniffs all traffic on `eth0` containing an HTTP signature and dumps from the signature to the packet's end. |
| SYN flood (DoS) | `hping3 -S 192.168.1.1 -a 192.168.1.254 -p 22 --flood` | Uses a spoofed source (`-a`) and flood mode to overwhelm a target — this is an attack technique, included here for completeness/detection purposes, not for use outside authorized testing. |

**IP spoofing with Hping3** (used later in `06-scanning-beyond-ids-firewall.md`):
```bash
hping3 www.certifiedhacker.com -a 7.7.7.7
```
`-a` sets a spoofed source address. **Note:** you cannot complete a real three-way handshake with a spoofed source, because the SYN/ACK goes back to the spoofed address, not to you.

### Hping3 Driven by AI (ChatGPT / shell-gpt)

The source material demonstrates using an AI assistant (via a `sgpt --chat ... --shell` wrapper) to translate plain-English requests into working hping3/Nmap commands, then execute them. Two worked examples:

**Prompt:** *"Use Hping3 to perform ICMP scanning on the target IP address 10.10.1.11 and stop after 10 iterations"*
```bash
hping3 --icmp --count 10 10.10.1.11
```
- `hping3` — invoke the tool
- `--icmp` — send ICMP packets
- `--count 10` — send exactly 10 packets
- `10.10.1.11` — target

**Prompt:** *"Run an hping3 ACK scan on port 80 of target IP 10.10.1.11"*
```bash
sudo hping3 --ack -p 80 10.10.1.11
```
- `--ack` — TCP ACK scan mode (sets the ACK flag)
- `-p 80` — destination port
- `sudo` — raw-socket access needs elevated privileges

This is a recurring pattern throughout the module: attackers increasingly prompt an AI shell-assistant in natural language ("scan X for Y and save to Z") rather than hand-typing every flag, letting the assistant translate intent into Nmap/Hping3/Metasploit syntax and even chain multiple commands with pipes and `awk`/`grep` post-processing.

## 2.3 Metasploit

**Source:** https://www.metasploit.com

Metasploit is an open-source penetration testing framework — infrastructure, exploit content, and payload delivery in one modular package. Its "any exploit + any payload" combinability is its defining feature. Beyond exploitation, it ships **auxiliary scanner modules** that cover much of what Nmap does, integrated into the same console workflow (discovery → exploitation → post-exploitation → reporting).

Example — listing port-scan auxiliary modules:
```
msf6 > search portscan
```
This surfaces modules like `auxiliary/scanner/portscan/ftpbounce`, `.../portscan/tcp`, `.../portscan/syn`, `.../portscan/ack`, `.../scanner/natpmp/natpmp_portscan`, `.../scanner/sap/sap_router_portscanner`, `.../scanner/http/wordpress_pingback_access`.

**AI-driven Metasploit example** — prompt: *"Use Metasploit to discover open ports on the IP address 10.10.1.22"*:
```bash
msfconsole -q -x "use auxiliary/scanner/portscan/tcp; set RHOSTS 10.10.1.22; run; exit"
```
- `-q` — quiet mode (suppress banner)
- `-x "..."` — run the quoted commands in sequence, then exit
- `use auxiliary/scanner/portscan/tcp` — load the TCP port-scan module
- `set RHOSTS 10.10.1.22` — target
- `run` → `exit`

## 2.4 NetScanTools Pro

**Source:** https://www.netscantools.com

An investigation/troubleshooting suite for discovering and monitoring devices on a LAN or over the Internet. Combines many discrete tools (automated + manual) under one roof, organized by category: active/passive discovery, ping tools, port scanner, DNS tools, packet-level tools, application-info tools. Attackers use it to enumerate IPv4/IPv6 addresses, hostnames, domain names, email addresses, and URLs, and to hunt for vulnerabilities/exposed ports.
