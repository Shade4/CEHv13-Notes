## How to Defend Against OT Hacking

A comprehensive OT hardening checklist:

- Regularly conduct a **risk assessment** to reduce the current risk exposure.
- Use **purpose-built sensors** to discover the vulnerabilities in the network inactively.
- Incorporate **threat intelligence** to uncover threats and protect assets by prioritizing patches.
- Regularly **upgrade OT hardware and software tools**.
- **Disable unused ports and functionalities**.
- Implement **secure configuration and coding practices** for OT applications.
- **Update systems** to the latest technologies and patch them regularly.
- **Maintain an asset register** to track the security of the data generated by the OT systems for detecting real-time and unsupported assets.
- Perform **continuous monitoring and detection** of the log data generated by the OT systems for detecting real-time threats and unsupported assets.
- **Train employees** with the latest security policies and raise awareness of the threats and risks.
- Use **strong and secure passwords** using hashing, and change the default factory-set passwords.
- Secure remote access through multiple layers of defense, including **multi-factor authentication, VPNs, firewalls, etc.**
- Implement **incident response and business-continuity plans**.
- **Secure the network perimeter** to filter and prevent unauthorized inbound traffic.
- Regularly **scan systems and networks** using anti-malware tools.
- **Restrict network traffic** by using time-rate-limiting and whitelisting attacks such as DDoS and brute-forcing attacks.
- **Harden the systems** by disabling unused services and functionalities.
- Regularly **patch vulnerabilities** released by manufacturers.
- Regularly **check the DNS logs** to detect any unauthorized DNS access.
- **Secure and update systems** that interact with the ICS/SCADA devices, as these can be compromised through legacy backup gateways.
- Employ **professional security red teams** to uncover vulnerabilities of critical infrastructure.
- Use **Intrusion Detection Systems (IDSs)** and flow-measurement systems to detect attack attempts at an early stage.
- **Ensure proper sanitization and validation** of the input to prevent attacks such as workflow overflow, timing injection, and XSS.
- **Use library calls** of external processes to recreate the desired functionality safely.
- Process all the **SQL queries** used in the ICS system using **prepared statements/parameterized queries**, avoiding vulnerable stored procedures.
- Use only **tested and familiar third-party web servers** for serving the ICS web application.
- Ensure that ICS vendors **design their systems to restrict unauthorized access** and grant the least privilege necessary for each function.
- Ensure the **integrity of transmitted messages** by appending a checksum to every message.
- Ensure ICS vendors **use cryptographic signatures** to validate software updates.
- Perform **audits and periodic code review** of all applications that process ICS protocol traffic.
- Perform a **source-code review** of all ICS applications that handle network traffic.
- Deploy **network-traffic monitoring tools** capable of deep packet inspection (DPI) to analyze and detect malicious activities within OT networks.
- Utilize **next-generation firewalls (NGFWs)** with deep packet inspection capabilities to filter and monitor traffic at network perimeters.

Mapping directly to the [10 OT vulnerabilities](08-ot-attacks-and-threats.md#ot-vulnerabilities) from file 08:

| # | Vulnerability | Solutions |
|---|---|---|
| 1 | **Publicly Accessible OT Systems** | Implement multi-factor authentication; use an enterprise-grade firewall and remote-access solution. |
| 2 | **Insecure Remote Connections** | Use a strong monitoring/authentication mechanism and robust password policies; implement appropriate security-patching practices. |
| 3 | **Missing Security Updates** | Test applications in a simulated environment before launching them live; employ a firewall and periodic device hardening. |
| 4 | **Weak Passwords** | Use separate username conventions for the corporate IT and OT networks; change default credentials at time of installation; perform security audits to meet compliance for both IT and OT networks. |
| 5 | **Insecure Firewall Configuration** | Segregate the corporate IT and OT network with a demilitarized zone (DMZ) for all connections; regularly monitor the DMZ. |
| 6 | **OT Systems Placed within the Corporate IT Network** | Restrict access on the OT network based on business need; establish a secure gateway between the OT and IT systems; perform a formal risk assessment. |

| 8 | **Lack of Segmentation within OT Networks** | Implement secure zoning and a multi-conduit architecture between ICS and non-critical processes; adopt a zero-trust security model that assumes no default trust. |
| 9 | **Lack of Encryption and Authentication for Wireless OT Networks** | Use strong wireless encryption protocols; use industry-standard cryptographic algorithms; conduct regular security audits. |
| 10 | **Unrestricted Outbound Internet Access from OT Networks** | Conduct a formal risk assessment; closely monitor and segregate OT systems from external networks; download security updates from a repository separate from the live OT network. |

## Securing an IT/OT Environment by Purdue Zone

IT/OT convergence is widely adopted in industries such as traffic-control systems, power plants, and manufacturing companies, but this also increases the attack surface across a shared IT/OT environment. Based on the Purdue model, IT/OT security is best divided into several zones, each with a level-appropriate security control:

| Zone | Purdue Level | Attack Vector | Risks | Security Controls |
|---|---|---|---|---|
| **Enterprise** | 5 & 4 (Enterprise Network and Business Logistics Systems) | Spear phishing, ransomware | Abusing infrastructure, access to the network | Firewalls, IPS, UBA, filtering, SSL inspection, antivirus, DLP |
| **Industrial DMZ** | 3.5 (IDMZ) | DoS attacks | Malware infections, network intrusions | Anti-DoS solutions, IPS, antivirus, application control, ALF |
| **Manufacturing** | 3 (Operational Systems) | Ransomware, bot infection, unsecured USB ports | Altering process, industrial spying, unsecured monitoring systems | Anti-bot, IPS, sandboxing, application control, traffic encryption, port protection |
| **Manufacturing** | 2 & 1 (Control Systems and Basic Controls) | DDoS exploitation, unencrypted protocols, default credentials, application/OS vulnerabilities | Altering industrial process, industrial spying | IPS, firewall, communication encryption using IPsec, gateway devices, use of PLC and I/O gateways at levels 1 and 0 |
| **Manufacturing** | 0 (Physical Process) | Physical security breach | Modifications or disruption to the physical process | Point-to-point communication, MAC authentication, additional security gateways at levels 1 and 0 |

*(Table 18.13 in the source courseware.)*

## Implementing a Zero-Trust Model for ICS/SCADA

OT networks are becoming an increasingly attractive target for attackers to disrupt industrial infrastructure. To stay ahead of increasingly sophisticated attacks, organizations must combine perimeter security with control access to sensitive assets, so access can only be granted on a verified, per-request basis rather than assumed from network location alone. Most OT networks are based on legacy systems or older architectures, which does not make them contain access-control mechanisms in advance to sophisticated attacks. Implementing a zero-trust model in an ICS network can allow an organization to provide robust access management for the validation of all the applications, users, and devices on the OT network.

**Steps to Implement a Zero-Trust Model in an ICS Network:**

1. **Defining the Network** — As the attack surface of an organization is constantly developing, it's a challenge to secure the entire enterprise. Instead, the zero-trust approach can be initiated through defining the attack surface by identifying the organizational assets, vulnerable data points, and critical applications within the control centers or factory floors.
2. **Mapping the Traffic** — The overall network traffic must be mapped and documented for a full understanding of how the network devices and other resources interact. Traffic mapping allows the OT team to gain complete visibility into the required security controls for securing critical data and applications.
3. **Architecting the Network** — After understanding the traffic flows, security analysts can implement a zero-trust architecture (ZTA) that meets the business requirements. It can be initiated with the introduction of a next-generation firewall (NGFW), which can add a segmentation gateway for critical assets that should be protected from wireless entry and lateral movement across the network.
4. **Developing a ZT Policy** — A zero-trust (ZT) policy should be implemented for whitelisting users and devices based on defining who, why, when, and what resources should be able to access the ICS network.
5. **Monitoring and Maintaining** — In the final stage, security analysts should ensure that the zero-trust architecture (ZTA) provides deep, real-time visibility into the ICS network so the traffic can be gain valuable insights into the network devices, and the OT team can manage and update the network devices as and when required.

## OT Security Solutions

The industrial and corporate sectors are rapidly digitizing their value chain, giving access to OT devices from a broader range of the internet. The cost of managing security in the heavy industrial sectors is being largely overlooked, leading to several security challenges and solutions.

Cybersecurity professionals should be examining the recent trends with suitable operational plans, as the industrial sector trend has increased with startup/DEM providers and new companies incorporate Value Risk Management (IRM). Some industries also provide a third line of defense by implementing internal audit functions.

### Firewalls

Firewalls are used in a network for monitoring and controlling the incoming and outgoing network traffic. Firewalls help in improving security controls by inspecting the traffic that traverses the gateway between the OT and IT networks. The attacker can use this gateway to bypass the network security between OT/IT environments and traversing them without security controls between OT/IT environments, moving further into critical assets in a DMZ away from the ICS systems.

Security professionals can use tools such as **FortiGate Rugged Next-Generation Firewalls** and **OTIFYD Next-Gen OT Firewall**.

### Unified Identity and OT Access Management

Access management helps industries to centralize security operations by adding, securing, changing, and removing user access to the OT systems. All this data is being provided with the organization's identity-management system, which can provide authentication.

Security professionals can use tools such as **Claroty**, **MetaDefender IT-OT Access**, etc. for identifying and managing access to industrial systems.

### Asset Inventory and Device Authorization

Asset Inventory helps in connecting only authorized devices to the OT network, and it can detect all the connected devices. It also detects the vulnerabilities in the devices, which are categorized based on the device manufacturer, version, and type. These devices can also be used to identify faults in the connected devices in the network, and it can enhance the efficiency of the device.

Security professionals can use tools such as **SCADAfence**, **Otbase**, **Guardian**, and **Dragos** for asset inventory and device authorization.

### OT Network Monitoring and Anomaly Detection

OT network monitoring is used for constantly monitoring the systems in industrial networks. These monitoring tools help in tracking the traffic in a more comprehensive manner, allowing for anomaly detection and prompt discovery of malicious activities. Most of these tools use machine-learning algorithms for easy detection and identification of malicious behaviors.

Security professionals can use tools such as **ISID** and **Rhebo OT Security** for OT network monitoring and anomaly detection.

## Decoys to Deceive Attackers

Decoys are honeypots used in the OT environment that incorporate deceptive technology to automate the creation of traps or decoys to lure the attackers before they get an opportunity to reveal their presence and preventing attackers from trying to penetrate the industrial network.

Security professionals can use tools such as **Attivo Networks ThreatDefend**, **Conpot**, and **GasPot** to protect the industrial network.
